# 双语与中文排版

网站界面支持 **English** 和 **简体中文**。文章不翻译，Notion 里写的是什么就显示什么；
界面文字、首页文案、日期格式、字体随语言切换。

## 语言怎么决定：看路径

每个页面在每种语言下各有一个地址：英文不带前缀，中文在 `/zh-CN` 下。

| 英文 | 中文 |
| --- | --- |
| `/` | `/zh-CN` |
| `/articles`、`/articles/page/2` | `/zh-CN/articles`、`/zh-CN/articles/page/2` |
| `/topics`、`/topics/fiction` | `/zh-CN/topics`、`/zh-CN/topics/fiction` |
| `/archive`、`/search?q=`、`/more`、`/articles/:slug` | 同样加 `/zh-CN` |

**同一个 URL 永远是同一种语言**——可以分享、可以被 CDN 缓存、搜索引擎能分别收录。其余信号只会触发**跳转**，不会改变某个地址的内容：

| 信号 | 作用（Node SSR） |
| --- | --- |
| `?lang=zh-CN` / `?lang=en` | `EN / 中文` 切换链接带上它：写入 `lang` cookie，再 302 到干净的路径（去掉 `lang`，保留其他参数）。旧的 `?lang=` 链接也因此仍然有效 |
| `lang` cookie | 访问不带前缀的页面而 cookie 是中文 → 302 到 `/zh-CN/…`；带前缀的地址以路径为准 |
| `Accept-Language` | 只在第一次访问首页 `/`（没有 cookie）时使用：中文浏览器 → 302 到 `/zh-CN` |

- 实现：`src/shared/i18n.ts`（`localePath`、`splitLocale`、`isPagePath`、`switchHref`，纯函数，有单元测试）+ `src/middleware.ts`。
  中间件把 `/zh-CN/x` **rewrite** 到同一个页面路由 `/x`，并写入 `Astro.locals.locale`（语言）和 `Astro.locals.path`（不带前缀的路径）；
  页面和组件只拼不带前缀的路径（`src/shared/routes.ts`），输出链接时统一经过 `localePath(path, locale)`。
- 不分语言的地址：`/api/*`、`/media/*`、`/uploads/*`、`/admin`、构建资源，以及带扩展名的文件（`/rss.xml`、`/sitemap.xml`、`/robots.txt`）。
  API 仍按 `?lang=` → cookie → `Accept-Language` → 英文 决定标签名等语言（`/api/site` 只认 `?lang`）；`/zh-CN/api/…` 是 404。
- `<link rel="canonical">`、`hreflang` 和 `sitemap.xml` 都用路径地址（`x-default` 指向英文）。RSS 与 robots.txt 只有英文。
- HTML 响应带 `Content-Language` 和 `Vary: Cookie, Accept-Language`（跳转取决于它们）。
- 在首页切换语言：脚本把当前滚动位置存进 `sessionStorage`，新页面直接回到原位，不重播开场动画。
- **静态快照**：写出的路径与 SSR 完全相同；没有服务器记住选择，所以切换链接去掉了 `?lang=`，根路径永远是英文，没有 cookie/`Accept-Language` 跳转。

## 文字放在哪里

| 内容 | 位置 |
| --- | --- |
| 导航、区块标题、按钮、分页、搜索提示、404 等界面文字 | `src/ui/i18n.ts`（`messages(locale)`；测试保证两种语言的键完全一致） |
| 首页引言、facts、标语、默认简介 | `src/content/site.ts` 的 `copy.en` / `copy['zh-CN']` |
| 浏览器脚本里的文字（如代码块的 **复制 / 已复制**） | 也在 `src/ui/i18n.ts`（`article.copyCode` / `article.copiedCode`），由页面以 `data-*` 属性交给脚本，脚本里不写死文字 |
| 站点简介（首页及 meta description）、首页引言和标语的覆盖值 | 后台 Settings：`site_about` / `site_intro`（英文），`site_about_zh` / `site_intro_zh`（中文）；`site_tagline` / `site_tagline_zh`（标语） |

| 后台 `/admin` 的界面文字 | `src/ui/scripts/admin/i18n.ts`（`en` / `zh` 两份，`zh` 的类型就是 `en` 的类型，缺键会编译失败）。语言：已保存的选择（localStorage `rra.admin.lang`）→ 浏览器语言 → 英文；切换后重新载入后台。服务器错误信息保持英文，中文界面按错误码在前面加中文说明；概览的“需要处理”由服务器只返回代码（`OverviewCheckCode`），文字在这里翻译 |

中文覆盖值留空时使用内置中文文案，**不会回退到英文**——中文页面上不会突然出现一段英文引言。

文章标题、摘要、标签按内容自动标注 `lang`（`contentLang`：含汉字即为 `zh`），所以英文界面上的中文标题仍按中文排版，反之亦然。

## 标签：同一个主题，每种语言只出现一次

文章不翻译，但标签是界面的一部分（首页“主题”、筛选、文章页）。`Fiction` 和 `小说` 指的是同一类文章，
所以它们被归成一个**主题**（`src/core/tags.ts`，纯函数，`tests/tags.test.mjs`）：

1. **对照表**：内置常见写作主题（`src/content/tags.ts`）+ 后台 Settings → Tag pairs（优先）。格式 `English = 中文`，逗号分隔别名。
2. **Notion 里的双语标签**：`Fiction / 小说`、`小说｜Fiction` 会被拆成两半，并让全站学会这一对。
3. 都不匹配：标签自成一个主题，两种语言都原样显示。

显示名按语言挑选：先用文章里实际出现过的该语言写法（出现最多的），没有就用对照表的第一个名字，再没有才用另一种语言。
同一篇文章同时标了 `Fiction` 和 `小说` 只算一次、只显示一个。

**主题页地址**：每个主题有一个 slug（`/topics/<slug>`），两种语言相同，由主题的 `key` 生成（`topicSlug`：NFKC、小写、
非字母数字的连续字符变成 `-`，最长 80；汉字等任何文字的字母都保留，如 `/topics/红房间`；完全没有字母数字时用 `t-<哈希>`）。
slug 只取决于 key，不随文章数变化；两个主题撞名时 key 排序靠前的保留原 slug，另一个加 `-<6 位哈希>`。
主题的**任何名称**都能找到它：`/topics/小说`、`/topics/Fiction` 301 到 `/topics/fiction`，所以旧链接 `?tag=小说` 也会一路跳到正确的主题页。
没有文章的主题（只在对照表里出现）和不存在的主题返回 404。

## 字体：让中文和英文是同一种声音

原设计的标志是 **Archivo 62% 宽、800 字重、全大写**——瑞士网格风格的窄体粗黑。
直接把同样的 CSS 用在中文上，浏览器会退回系统黑体的常规宽度：方正、偏细、字面比英文大写字母高一截，
标题在两种语言之间来回切换时，整页的“音色”就断了。

### 显示字体：Red Room Display SC

| | 英文 | 中文 |
| --- | --- | --- |
| 字形骨架 | Archivo（新怪诞体） | Noto Sans SC / 思源黑体（同属无衬线黑体） |
| 宽度 | `font-stretch: 62%` | 字形**压缩到 82%**（长体） |
| 字重 | 800 | **900（Black）**——压窄后竖笔会变细，Black 补回与 Archivo 800 相同的灰度 |
| 字高 | 大写字母约占 em 的 70% | `size-adjust: 88%`，让汉字与大写字母一样高 |
| 大写 | `text-transform: uppercase` | 汉字没有大小写，不受影响 |

所以 `NOTION 写作工作流 2026` 这样的中英混排标题可以共用一条基线、一样的高度和粗细，不需要给中文单独设字号。

**为什么要生成一个字体文件，而不是用 CSS 压缩？**
`transform: scaleX()` 只改变绘制，不改变排版盒子：标题后面会留出空白、换行位置是按原宽度算的。
目前也没有带宽度轴的中文字体。把轮廓离线压缩一次，浏览器拿到的就是一款“本来就窄”的普通字体，
换行、选中、混排都和英文设计一样工作。

**生成方式**（`scripts/fonts/build-display-sc.py`，只在调整参数时需要重新运行）：

```bash
npm ci                                        # 带来 devDependency @fontsource-variable/noto-sans-sc
pip install fonttools brotli                  # 或 pip install --target /tmp/pylib … 再加 PYTHONPATH=/tmp/pylib
python3 scripts/fonts/build-display-sc.py     # 输出到 public/fonts/display-sc/
```

脚本沿用 fontsource 的 unicode-range 切片（96 片，共约 2.3 MB），浏览器只下载页面上真正出现的汉字所在的切片；
emoji 等 U+1F000 以上的码位不收录，交给系统字体。字体按 SIL OFL 1.1 改名为 “Red Room Display SC”，许可证在同一目录。

实测（中文首页有 8 篇中英文章时）：中文首页下载 11 片约 328 KB，中文文章页 6 片约 174 KB，没有中文的英文页面 0 字节。
样式表 `display-sc.css` 以非阻塞方式加载（`media="print"` + `onload`，带 `<noscript>`），字体用 `font-display: swap`，不会拖慢首屏。

### 正文：系统黑体

正文（Archivo 400–650）配的是系统黑体：苹方 / 冬青黑体 / 微软雅黑 / Noto Sans CJK（`--cjk`）。
它们与 Archivo 同属无衬线黑体，屏幕上已经调校得很好，并且**零下载**——
一篇长文用到的汉字会分布在几十个切片里，正文用 webfont 意味着每篇文章要下载 1 MB 以上。

字体栈总是**拉丁字体在前**（`'Archivo Variable', …, var(--cjk)`），所以混排时字母和数字始终是 Archivo，汉字才落到中文字体。

### 哪些元素用显示字体

`src/ui/styles/base.css` 里有一张列表：所有用了 `font-stretch: 62%` 的元素都必须在里面
（首页 `.count` `.bar .brand` `.sec` `.row .t` `.go`，内页 `.site-brand` `.prose h1` `.page-head h1`，/more 的 `.mp-head h1` `.pub-title` `.tc-no` `.tc-title` `.mail-big`，后台 `.admin h1` `.admin-sec` `.me-num` `.set-group legend` `.set-legend` `.ov-name` `.ov-stat dd`）。
`tests/i18n.test.mjs` 会扫描所有样式表：新增窄体元素却忘了加进列表，测试会失败。

### 其他中文细节（全部在 `src/ui/styles/cjk.css`）

规则都写成 `:lang(zh)`，同时作用于中文界面和英文界面里的中文内容。

- **行距**：汉字占满整个 em 框，英文大写只占约 70%。英文标题的 .82–1 行距会让换行的中文上下相碰，多行元素加大行距（列表标题 1.12、文章标题 1.1、引言 1.32、正文 1.9）。
- **字距**：英文小标签的大字距在中文里像字与字之间的空洞，统一收小；导航、元信息保留少量字距。
- **引言**：中文字面更“满”，字号比英文略小（`clamp(1.7rem, 3.7vw, 3.7rem)`）。带署名的名言（句末“——作者”，由 `src/core/quote.ts` 拆分）字数少，改用更大的字号 `clamp(2.2rem, 5.2vw, 5.6rem)` 和更宽的栏（12 栏中占 10 栏），桌面上排成两行正文加一行右对齐、略暗的署名；默认中文引言在“个性”后用换行符固定 14／14 的构图，逐词动画保留此换行，窄屏恢复自然换行；署名最后点亮。逐词点亮动画用 `Intl.Segmenter` 按词切分，标点粘在前一个词上，不会单独亮起一个逗号。
- **强调**：中文没有斜体，机器倾斜的黑体很难看。文章里的 *斜体* 在中文中显示为**着重号**（字下加点）。
- **正文**：两端对齐、`line-break: strict`（标点避头尾），支持的浏览器会自动在中英文之间加空隙（`text-autospace`）。
- **日期**：中文为 `2026年10月27日`，带时间时 `2026年10月27日 21:30`；显示的是作者在 Notion 里写下的时间，不做时区换算。

## 新增一种语言

1. `src/shared/i18n.ts`：把语言加进 `LOCALES`，并在 `parseLocale` 里写好匹配规则。
2. `src/ui/i18n.ts`：补一份字典（测试会检查键是否齐全）。
3. `src/content/site.ts`：补一份 `copy`。
4. 如需后台覆盖：`contracts.ts` 的 `SettingKey` 与 `services/settings.ts` 的 `COPY_KEYS`。
5. 非拉丁文字的标题如果要配窄体，参照 `build-display-sc.py` 生成对应的显示字体，并在 `--display` 字体栈里加上。
